## 화요일 6/16 — SELECT / WHERE / ORDER BY

**study 기록 파일:** `study/260616_select-where-orderby.md`

> 월요일은 repo·환경 세팅. 화요일부터 1주차 「월」 주제로 시작한다.

### 1단계 · 읽기 (15분)

- MySQL 입문서: SELECT, FROM, WHERE, ORDER BY, LIMIT 해당 절 훑기
- **실행 순서**만 확실히: `FROM → WHERE → SELECT → ORDER BY`

### 2단계 · 손으로 쓰기 (10분)

아래 구조를 해석 순서와 함께 **3번** 손으로 작성:

```sql
SELECT   컬럼
FROM     테이블
WHERE    조건
ORDER BY 컬럼;
```

### 3단계 · 실행 (15분)

아래 4가지를 직접 실행하고 결과 행 수·정렬 확인:

1. 조건 없는 SELECT
2. WHERE 조건 1개
3. WHERE 조건 2개 (AND)
4. ORDER BY 추가

### 4단계 · 업무 연결 (15분)

- 업무 프로시저 **1개**만 연다
- SELECT / FROM / WHERE / ORDER BY 구문만 형광펜(또는 주석)으로 표시
- **전체 해석은 하지 않는다** — 오늘 절만 본다

### 5단계 · 회고 (5분)

```text
오늘 알게 된 것:
아직 헷갈리는 것:
업무 코드에서 본 것:
```

## 수요일 6/17 — INNER JOIN / LEFT JOIN

**study 기록 파일:** `study/260617_join.md`

### 1단계 · 읽기 (15분)

- INNER JOIN vs LEFT JOIN 차이 훑기
- **왜 JOIN이 필요한지** (테이블 2개의 관계)만 이해

### 2단계 · 손으로 쓰기 (10분)

아래를 손으로 2번씩 작성:

```sql
-- INNER: 양쪽 모두 매칭되는 행만
SELECT ...
FROM   A
INNER JOIN B ON A.id = B.a_id;

-- LEFT: A 전체 + B 매칭 (없으면 NULL)
SELECT ...
FROM   A
LEFT JOIN B ON A.id = B.a_id;
```

### 3단계 · 실행 (15분)

- 같은 기준 테이블 2개로 INNER / LEFT 각 1회 실행
- **결과 행 수 차이**를 메모 (LEFT가 더 많거나 같은 이유)

### 4단계 · 업무 연결 (15분)

- 어제 표시한 프로시저 또는 **다른 프로시저 1개**
- JOIN 구문만 찾아 표시
- ON 조건이 **어떤 컬럼끼리 연결하는지** 한 줄로 적기

### 5단계 · 회고 (5분)

- 특히 「INNER와 LEFT 결과가 어떻게 달랐는지」 반드시 적기

## 목요일 6/18 — GROUP BY / 집계 / 중복 행

**study 기록 파일:** `study/260618_group-by.md`

### 1단계 · 읽기 (15분)

- GROUP BY, COUNT / SUM / AVG / MAX / MIN 훑기
- **왜 GROUP BY가 필요한지** (행 묶기)만 이해

### 2단계 · 손으로 쓰기 (10분)

```sql
SELECT   그룹컬럼, COUNT(*)
FROM     테이블
WHERE    조건          -- 선택
GROUP BY 그룹컬럼
HAVING   집계조건;     -- 선택
```

실행 순서: `FROM → WHERE → GROUP BY → HAVING → SELECT`

### 3단계 · 실행 (15분)

1. GROUP BY 없이 COUNT(*) — 전체 행 수
2. 컬럼 1개 기준 GROUP BY + COUNT
3. HAVING으로 그룹 필터 1회

### 4단계 · 업무 연결 (15분)

- 프로시저에서 GROUP BY 또는 집계 함수(COUNT, SUM 등) **1곳**만 표시
- 「무엇을 기준으로 묶는지」 한 줄로 적기

### 5단계 · 회고 (5분)

- 「중복 행이 왜 생기는지 / GROUP BY로 어떻게 줄이는지」 적어보기

## 금요일 6/19 — 파라미터 / 변수 / 조건문 (IF, CASE)

**study 기록 파일:** `study/260619_params-condition.md`

### 1단계 · 읽기 (15분)

- MSSQL 기준: `@파라미터`, `DECLARE @변수`, `IF`, `CASE` 훑기
- MySQL 책과 다른 점은 **메모만** (깊게 비교하지 않음)

### 2단계 · 손으로 쓰기 (10분)

```sql
-- 흐름만 손으로
DECLARE @var INT = 0;

IF @var = 0
    SELECT 'zero';
ELSE
    SELECT 'other';
```

### 3단계 · 실행 (15분)

- 간단한 IF / CASE 예제 각 1개 실행 (로컬 또는 테스트 DB)
- `@param`에 값을 바꿔 넣었을 때 **분기 결과** 확인

### 4단계 · 업무 연결 (15분)

- 업무 프로시저 1개에서 **파라미터 선언부**와 **IF/CASE 블록 1곳**만 표시
- 「입력값 → 분기 → 어떤 쿼리로 가는지」 화살표로 스케치 (종이·메모장 OK)

### 5단계 · 회고 (5분)

- 「프로시저 맨 위 @파라미터가 아래 어디에 쓰이는지」 1개만 추적해 적기
